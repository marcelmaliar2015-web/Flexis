# Mail Check mailbox and OpenAI

## Context

Job seekers need interview mail kept and application receipts discarded. Mail Check needs its own mailbox connection, separate from Job Application Gmail used for sheets and pipeline. Classification needs a model; the user pays only for an OpenAI API key.

## Decision

Mail Check is a signed-in module under `/mail-check` with Need action, Inbox, Check, Log, and Settings tabs. It stores per-user mailbox connections in `mail_connections` (any number of Gmail and Outlook accounts; see [023-multi-mailbox-mail-check.md](023-multi-mailbox-mail-check.md)). Gmail and Outlook connect and disconnect live on Mail Check Settings. Job Application Gmail stays on Job Application Settings for Sheets and Drive.

Gmail OAuth uses `openid`, `userinfo.email`, and `gmail.modify`. Outlook OAuth uses Microsoft identity with `User.Read`, `Mail.ReadWrite`, and `MailboxSettings.ReadWrite` through Microsoft Graph. Outlook requires an admin to save the Microsoft client on Settings. The API returns `outlookAvailable: true` when that client is saved and `Microsoft:RedirectUri` is set. Microsoft OAuth HTTP calls use a 60 second timeout.

Gmail uses labels and stars. Flexis creates classifier labels under the `Flexis/` namespace in Gmail (for example `Flexis/Scheduled`) so names do not collide with Gmail system labels. Outlook uses master categories with the same `Flexis/` names. Pin on Gmail adds the classifier label and stars the message. Pin on Outlook adds the category, clears any follow-up flag, and sets the native Outlook pin properties so the message stays at the top of the inbox. Trash moves it to trash. Keep leaves the message in place. Every classified message gets its classifier label or category before trash or keep runs. Pin, trash, and keep all mark the message read in the mailbox. Each classify run reloads Mail Check settings from the database before trash enforcement and before each message so label actions match Settings. Each run first lists mail that already has a Flexis trash-action label and still sits in the inbox, then trashes it so Settings changes apply to already-labeled mail. Gmail and Outlook inbox lists omit trashed or deleted items.

On first use Flexis creates classifier labels on each connected mailbox. A check reads inbox and junk (Outlook) or inbox, spam, and category tabs (Gmail). Outlook candidates use `/me/messages` so inbox subfolders are included; sent, deleted, draft, archive, and outbox are excluded. It does not scan sent, drafts, or archive as primary targets. Check all covers every connected mailbox; Check covers one. Each API run classifies up to three unprocessed messages per mailbox. Candidate search skips messages already in Flexis history and stops at the first fresh message on each page instead of walking the whole inbox. If a message was trashed, moved, or labeled by hand before Flexis applies an action, Flexis re-reads the message after classification and skips or records it without failing the run. There is no calendar cutoff; order is always newest first. Messages already labeled on the mailbox are excluded from classify candidates. Check all keeps requesting runs until candidates are exhausted.

The user's OpenAI key classifies each new message with a configurable prompt on Settings (default includes label examples). The model must return JSON with one `label` field: `rejected`, `applied`, `schedule`, `scheduled`, `assessment`, `availability`, `success`, `other`, or `less_important`. `less_important` is for job-board digests, recommendations, recruiter cold suggestions, ads, newsletters, and account or security noise; default action is trash. Classification input uses full subject plus body clipped to 20,000 characters (head and tail kept when longer). Default model is `gpt-4.1-mini`. Empty OpenAI replies retry with a larger token budget and alternate request shape; if classification still fails, Flexis applies the `other` label action, records the fallback in the Log, and continues the run so one bad reply cannot stall auto-check. Settings also store per-label mailbox actions: `pin`, `trash`, or `keep`, and which labels appear on the Need action tab (default schedule, assessment, availability). Processed message ids and classified labels are stored per mailbox so Flexis does not pay to classify them again.

Auto-check runs on the API every 20 seconds for each user with `autoCheckEnabled`, a saved OpenAI key, and at least one mailbox (see [027-mail-check-server-auto-check.md](027-mail-check-server-auto-check.md)). The browser does not drive classification; the AppBar shows `MailCheckAutoStatus` from settings and `GET /api/mail-check/run/progress` while auto-check is enabled. Each cycle classifies up to three messages per API call and may chain up to five follow-up calls when `hasMore`. `POST /api/mail-check/run` returns a `timing` breakdown (`lockMs`, `tokenMs`, `labelsMs`, `scanMs`, `fetchMs`, `classifyMs`, `applyMs`) summed for that API round; `lockMs` is the wait for the per-user classify lock. `GET /api/mail-check/run/progress` returns live stage, message, counts, and lock-wait state. The server logs each stage with structured `MailCheck` log lines. Manual Check waits up to 20 seconds for the per-user lock if a server auto run is active. Every message action and each completed server round is written to `mail_check_action_logs` and listed on the Log tab via `GET /api/mail-check/logs` (see [026-mail-check-action-log.md](026-mail-check-action-log.md)).

## Consequences

Do not reuse Job Application `google_connections` for Mail Check. Do not store the OpenAI key in the browser. New product modules still add a left-nav item and a route under `AuthenticatedLayout`.
